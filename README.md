# Поиск максимального значения в большом массиве данных

Учебный проект на Go: поиск максимума в слайсе целых положительных чисел сначала
в один поток, затем параллельно в 8 горутинах.

## Требования

- Go 1.24.1 или новее.
- Для запуска с константой `SIZE = 100_000_000` на 64-битной системе требуется
  примерно 800 МБ памяти только под слайс `[]int` плюс накладные расходы runtime.

## Запуск

```bash
go run .
```

Программа выводит максимальное значение и время поиска в микросекундах для
последовательного и параллельного вариантов.

## Реализация

- `generateRandomElements(size int) []int` генерирует `size` положительных
  случайных чисел через `math/rand`. При `size <= 0` возвращает пустой слайс.
- `maximum(data []int) int` выполняет линейный поиск максимума. Для пустого
  слайса возвращает `0`.
- `maxChunks(data []int) int` делит слайс на `CHUNKS = 8` частей, ищет максимум
  в каждой части в отдельной горутине и затем выбирает максимум из локальных
  результатов. Остаток от деления попадает в последнюю часть. Для пустого
  слайса возвращает `0`; для слайса меньше `CHUNKS` использует последовательный
  поиск, чтобы корректно обрабатывать в том числе отрицательные значения.
- `main` генерирует данные, измеряет время обоих вариантов через `time.Since`
  и выводит результат в микросекундах.

## Крайние случаи

| Ситуация | Поведение |
| --- | --- |
| `generateRandomElements(0)` или отрицательный размер | пустой слайс |
| `maximum(nil)` / `maximum([]int{})` | `0` |
| `maximum` с одним элементом | этот элемент |
| `maxChunks(nil)` / `maxChunks([]int{})` | `0` |
| `maxChunks` с длиной меньше `CHUNKS` | последовательный поиск |
| длина не делится на `CHUNKS` | остаток обрабатывается в последней горутине |
| отрицательные значения | корректный максимум без паники |

## Сложность

- Последовательный поиск: `O(n)` времени, `O(1)` дополнительной памяти.
- Параллельный поиск: `O(n)` суммарной работы, `O(CHUNKS)` дополнительной
  памяти; критический путь при достаточном числе ядер — примерно `O(n / CHUNKS)`.

Фактическое ускорение зависит от числа доступных ядер, `GOMAXPROCS`, пропускной
способности памяти и планировщика Go. Восемь горутин не гарантируют ровно
восьмикратное ускорение.
